# P03 已知问题与设计说明

> 更新：2026-10-30 ｜ 状态标注：[已验收] = 验收通过但行为值得说明；[待办] = 需后续处理

## 1. [已验收] E09 拒绝方返回 400 而非 409

并发出库的失败方返回 `400 INSUFFICIENT_STOCK`，不是 `409 STOCK_CONFLICT`。

- 原因：B 的实现是条件更新（CAS）失败后重读库存再校验——此时库存确已被抢完，400 是真实业务语义；409 STOCK_CONFLICT 是重试耗尽后的兜底路径（`backend/Services/StockTransactionService.cs`）。
- 验收影响：无。两者均在契约错误码表内，核心验收点（不超卖、恰 N 笔成功、余额严格递减）全部成立。`tests/e09_e13_concurrency.py` 同时接受两种拒绝码。

## 2. [已验收] E13 幂等重放返回 200（非 201）

同 RequestId 重放返回首次结果的实体，HTTP 200；仅首次创建返回 201。符合「重放返回首次结果」契约语义。

## 3. [已验收] 种子导入在有流水时拒绝执行

`--seed-import` 检测到任何库存流水即拒绝（保护生产数据），输出提示而非静默覆盖。重置基线需先 drop 库（见 deployment.md）。注意：drop 前必须停止后端进程，否则 LocalDB 连接占用导致失败。

## 4. [已验收] 登录限流全局生效

每 IP 每分钟 10 次，超限 429 RATE_LIMITED。自动化脚本连续跑登录时注意节流；冒烟脚本每轮仅 2 次登录。

`admin/Admin@123!`、`operator/Operator@123!` 是验收默认账号，生产交付前必须修改（README 已标注）。

## 6. [待办] 移动端表格窄屏可读性

375px 下商品/报表表格通过横向滚动保证可读，未做卡片式重排（验收标准仅要求响应式可用，已达标）。如需增强可在后续迭代改为卡片布局。

## 7. [已验收] 前端时间显示为本地时区

API 全部 UTC ISO 8601；前端展示时转换为浏览器本地时区。仪表盘 7 日净变更按 UTC 自然日聚合（契约口径），跨时区用户看到的「今日」柱可能与本地日历日有偏移，属契约定义内行为。
